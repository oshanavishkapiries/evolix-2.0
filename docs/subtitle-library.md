# Subtitle library

Extend `subtitles` so existing CMS references and subtitle IDs stay valid. New origin fields identify alternate tracks; private uploads and their translations are visible only to their owner and explicitly invited viewers. Shared page caches never contain private tracks. Viewers fetch their private library from the authenticated API.

Migration `drizzle/0016_subtitle_library.sql` is not applied to production by the agent. It backfills existing tracks with `source='auto'`, shared visibility, and zero scores through column defaults. A generated `origin_key` column normalizes a null origin reference to an empty string; partial indexes make webhook retries idempotent while allowing independent origins in each language. OpenSubtitles origins are provider file IDs. Translation origin references are the source track UUID. The migration journal and Drizzle snapshot are included.

Apply through the project's migration workflow after reviewing a backup and the SQL. Deploy the schema and updated engine before the new application, and do the migration and the app deploy back to back: the migration drops the old per-language unique keys, so the previous app's subtitle upsert in `lib/evo/promote.ts` fails until the new app is live. Pause new ingests during that window; the engine retries its completion webhook. Successful viewing sessions score once each; activity rows retain distinct viewer history and deduplicate good votes and reports per user and track. A successful play needs 60 seconds of actual playback with loaded subtitles; the server also requires 60 elapsed seconds after the start request. Repeated submissions of the same play ID do not inflate the score; a later successful viewing session can score again. Daily quota reservations use atomic database writes. Upload limits are 10 attempts per user/day, up to 2 MB each; new translations are limited to three per user/title/day. Joining an existing engine job does not consume another translation reservation.

Provider downloads skip a few bad cues (overlaps, zero-length, empty) and are accepted while at least 90% of cues are good; uploads stay strict. Scores count one successful play per viewer, track and day, and score changes do not expire the catalog cache (only a report that hides a track does). Automatic search results of "nothing found" are remembered for 10 minutes per title. Downloads retry three times per candidate (10-second timeouts, 0.5/1.5-second backoff), up to five candidates per language. Text must parse to at least 50 cues for movies or 20 for episodes. Uploads additionally check ordered timestamps and, when runtime is known, a final cue within 15% of that runtime. Script/style content and markup are stripped before storage. Search choices are signed, viewer-bound, and expire after 30 minutes; browsers never receive provider download links.

The compact menu offers Off, best Sinhala, best English, and More options. More options lists the library, search, uploads, translation from a selected English source, votes and reports. The existing dual subtitle slots and synchronization tools remain available. Timing and explicit track choices are saved per title with localStorage failures handled.

Uploads are promoted after three distinct other viewers complete a successful play while the source has no reports. An owner can copy a signed invitation from More options; redeeming it grants that signed-in viewer access to the private source and its translations. Invitations expire after seven days. Source promotion also shares its translations. Restoring a reported track is an explicit admin action; historic reports remain recorded. Admin deletion calls the owning engine's existing CDN delete endpoint for the source and its translations before deleting rows. If the engine can no longer delete a file (already gone), `DELETE ...?force=1` removes the database rows only. A CDN URL still referenced by another track is retained.

## Local checks

- `pnpm test:subtitles`: migration, database and app API tests in an in-memory PGlite database; external calls are mocked.
- `pnpm test:subtitles:engine`: stdlib unit tests in `evo-engine/test/.venv`, with temporary paths, fake storage/translation/provider responses and throwaway credentials. If needed, create that venv and install `evo-engine/requirements.txt`.
- `pnpm test:subtitles:e2e`: Playwright against an isolated Vite player harness. All `/api/*` and media requests are mocked. It needs Chromium (`pnpm exec playwright install chromium`) and ffmpeg for the local video fixture.

These checks do not use the database URL from `.env` or contact production engine nodes. The production build was checked with dummy environment values. Live-provider availability and CDN credentials still depend on deployment configuration.

The optional official OpenSubtitles API key and secret-token rotation remain owner configuration decisions; this implementation retains the existing legacy provider.

## Rollback

First revert the app and stop writers. Export the library, then retain one shared track per parent/language (highest score, last use as tie-breaker). Multi-track rows must be archived or removed before restoring the old unique constraints. Drop `subtitle_activity`, `subtitle_grants`, `subtitle_plays`, and `subtitle_quota`; drop the two origin indexes and added subtitle columns (including generated `origin_key` before `origin_ref`); restore `subtitles_movie_language_uq` and `subtitles_episode_language_uq`; then drop the two new enum types. Rolling back discards library activity and alternate tracks unless exported.
